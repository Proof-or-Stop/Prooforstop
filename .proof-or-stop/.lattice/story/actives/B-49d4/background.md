## Key Insights

packages/main/tests/red/red-w2c-validate-registration.mjs guards registration by walking a hardcoded REQUIRED_VALIDATE_COMMANDS list and asking "is each one registered". It never walks the disk asking "is each member decided", so it is structurally blind to a new member nobody registered. The probe proved it: a genuine member of THAT guard's population - which is the dist tasks packages/main/dist/tasks/red-evidence-*.js, not the tests/red directory - deliberately exiting 1 and registered nowhere left the guard at exit 0 printing a confident success line reporting "all 3" while 4 members were on disk; the count comes from the expectation's length, so it can never reveal the gap. A control run proved the guard does bite when a listed command is de-registered, so the blindness result is not a broken experiment. Two compounding facts make it matter more than the blindness alone. First, the guard itself is not registered in lattice.config.json, so even in the direction where it does bite it never runs under lattice validate. Second, and this is a DIFFERENT population that no guard covers at all: 18 of 31 harnesses in packages/main/tests/red/ are not registered; 3 are spawned transitively by red-b2aa7-chk007-receipt.mjs, leaving 15 that no automated path ever executes. Measured on 2026-07-27, all 18 currently pass and take 37 seconds in total, so nothing is silently broken today and the cost of running them is negligible.

## Solution Tradeoffs

The repository already contains a working reference for the correct shape: red-b2aa7-chk007-receipt.mjs was rewritten during B-2aa7 to enumerate its population from disk and require every member to be either registered or listed as an explicit exclusion carrying a stated reason, including itself with no self-exception, and its bite was proven in both directions. Copying that shape is mechanical. The alternative of simply appending the missing entries to the hardcoded list was rejected: it fixes today's population and leaves the instrument blind to the next addition, which is the actual defect. The two populations must not be conflated: fixing the dist-task guard leaves tests/red still unguarded, because red-b2aa7-chk007-receipt.mjs derives only over red-b2aa7-*. Registering the 18 without also installing a derived guard over the whole tests/red population would fix today's members and leave the next addition to slip through unnoticed exactly as these did - treating the symptom while omitting the instrument. A second decision is what to do about harnesses that should genuinely not run under validate: those need an explicit exclusion carrying a reason rather than silent absence, so the record distinguishes a decision from an oversight.
