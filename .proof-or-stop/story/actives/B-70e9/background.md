## Trigger Event
On 2026-07-10 a forensic token-burn audit found the usage ledger .lattice/usage/llm-usage.jsonl contains only 4 probe records from 2026-06-19 while the real burns were host-side and invisible: a 30-hour Codex Desktop thread in the legacy Work/Orchestrate directory accumulated 368.9M cumulative input tokens across ~4,700 turns, five parallel codex exec reviewers for one story burned ~16M input in about one minute, and Claude reviewer sessions for recent stories burned 4-8M new input each. Attribution required manual archaeology over ~/.codex/sessions rollouts and ~/.claude/projects transcripts. B-d8ef (DONE) standardized canonical noninteractive launcher specs for codex/claude/agy, creating the natural choke point this story builds on.

## Key Insights
The ledger dispatch seam only covers lattice dispatch_run leaf calls; reviewer launches, quorum host reviews, the autopilot repair step, and readiness probes are spawned outside the ledger, so the highest-volume runs are unrecorded. Verified host facts that override earlier assumptions: (1) agy print mode surfaces no per-call usage on any stable surface (B-fbb6 verified; re-probed 2026-07-10), so agy rows must record usage.source=unavailable rather than fabricated counts; (2) the canonical codex launcher includes --ephemeral, so no rollout file is written for canonical runs and codex usage must be parsed from the exec --json stdout terminal turn.completed event usage object with input_tokens, cached_input_tokens, output_tokens, reasoning_output_tokens (verified on codex-cli 0.141.0); (3) claude stream-json result usage is already parseable via parseClaudeCliOutput. Retro attribution for sessions lattice did not launch is only possible from host transcript stores and is an estimate, never authoritative accounting.

## Solution Tradeoffs
M1 adds one host-run choke-point command that reuses the existing dispatch-usage seam (preflight estimate, provider-reported final, hard-budget guard) instead of introducing a second writer path, preserving the single-writer completeness guarantee from the usage-ledger execution plan; reviewer and quorum guidance then routes future host runs through it. Rollout-file parsing for codex was considered and rejected for M1 because the canonical launcher is ephemeral; the sweep (M2) still reads rollouts for desktop and foreign sessions. M2 is a read-only scan of ~/.codex/sessions and ~/.claude/projects since a cutoff emitting human and JSON attribution reports labeled non-authoritative; it does not backfill the ledger and does not intercept interactive desktop sessions.
