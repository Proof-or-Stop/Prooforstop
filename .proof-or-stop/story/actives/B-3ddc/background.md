## Trigger Event
On 2026-07-11, during story B-3928 forensics, a `lattice host_run --host codex` run failed and the ledger final said only `unavailableReason: "no_turn_completed_usage_event"`. The real cause — codex exec emitted `{"type":"turn.failed","error":{"message":"...status 400... The 'gpt-5.6-sol' model requires a newer version of Codex. Please upgrade to the latest app or CLI and try again."}}` (a Desktop-written config model ahead of the PATH CLI) — had to be dug out of a Codex Desktop rollout, because host-run.ts retains only `turn.completed` lines and `--ephemeral` leaves no codex session file.

## Key Insights
The default streaming runner (packages/main/src/core/host-run.ts) deliberately retains only ONE bounded usage-bearing line (last-wins, 1 MiB cap, F-013/F-026 truncation discipline) — full transcripts are passed through live and never buffered. The failure event is itself a single JSON line on the same stream, so retaining the last `turn.failed`/terminal `error` line under the identical cap discipline adds bounded state only (a second retained line), no transcript accumulation. The ledger's honest-unavailable contract must hold: a retained failure line refines the REASON of an unavailable final; it never becomes usage, and a real `turn.completed` usage always wins (provider-reported final unchanged).

## Solution Tradeoffs
A second bounded retention lane (reuse the existing UsageLineScanner class with a failure-line predicate) is preferred over (a) widening the single retainer to match both event types — last-one-wins across mixed types could evict a genuine usage candidate and change existing provider-reported behavior — and over (b) persisting full transcripts or codex session files, which breaks the bounded-memory design and the --ephemeral privacy expectation. The digest in `turn_failed(<digest>)` is a short sanitized excerpt of error.message (innermost human-readable message when the message is nested JSON), not a hash, because the point is human diagnosability in the ledger row.

## Conversational Texture
The user runs unattended multi-host quorum loops and reads ledger finals when a host run dies; they care that the ledger tells the truth about WHY usage is unavailable without a forensic dig through Desktop rollouts. The acceptance texture is: run fails with a version-skew 400 → the ledger row itself names turn.failed and the upgrade message; nothing changes for healthy runs; usage is never invented.
