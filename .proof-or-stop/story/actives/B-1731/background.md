## Trigger Event
Opened 2026-06-24 from a gap observed in this program: Red/Repro/Spike is a soft norm, not a gate. The repro intake commands (repro_probe, repro_review_set, spike_record, spike_review_set, story_create_from_repro) are fully implemented in packages/main/src/handlers/repro-intake.ts, and proof-admissibility.ts already reserves the STORY_INTAKE consumer + evidence-candidate scope (B-0985/B-0405), but packages/main/src/handlers/story-create.ts has NO preflight. So nothing triggers or requires repro-first at story creation.

## Key Insights
Without a story_create preflight, repro-first is candidate-only with zero trigger: the system neither auto-runs nor requires repro/spike, so high-risk/bugfix/code-verifiable stories can be created and advanced with no repro evidence. The discipline relies on agent memory, which leaks (proven this session). story_create is the earliest, cheapest, best-informed hook (type/priority/riskSignals are already present). The downstream is ready: story_create_from_repro already binds a reviewer-accepted candidate. The only missing piece is the STORY_INTAKE-consumer preflight on plain story_create that classifies the task and warns/blocks when a repro-first-required task has no bound accepted candidate, steering to repro_probe + story_create_from_repro.

## Solution Tradeoffs
Implement a warn-first STORY_INTAKE preflight by REUSING proof-admissibility (STORY_INTAKE consumer, evidence-candidate scope, reason codes) — do not build a parallel system. Classify repro-first-required (type=bug OR high-risk riskSignal OR code-verifiable behavior change) vs bypass-eligible (doc/metadata/chore, explicit quick-fix, low-confidence). Config reproFirstPreflight.mode = off|warn|enforce (warn default). Bypass requires a recorded reason (written as a repro-first-bypass local-diagnostic artifact, surfaced in session_brief). The preflight MUST fail-OPEN on its own error (never block story creation on a checker bug). It checks presence + reviewer-acceptance of a candidate to inform story creation (a use the plan explicitly permits); it does NOT consume the candidate as lifecycle proof (that is the PLAN->DEV/integration story). Enforce rollout is deferred (warn-first + grandfather).

## Conversational Texture
Operator directive: make Red/Repro/Spike a gate, not memory. This story is the earliest of three layers (story_create preflight here; PLAN->DEV backstop and DONE red->regression conversion are separate). It dogfoods the repro-first discipline on a high-risk, code-verifiable change to the story-intake hot path; fail-open + warn-first keep that hot path safe.
