## Trigger Event
During story B-6de6 (the storyFilesHash-authoritative review-assurance-floor fix) on 2026-06-24, a Claude concept lane (F-002) and the Codex host-2 reviewer independently flagged (rated medium) that evaluateReviewEscalation in packages/main/src/core/review-escalation.ts (~line 439) recomputes freshness with currentMaterialHash(args.projectRoot) and currentStoryFilesHash(args.projectRoot), while review-assurance-floor.ts uses currentMaterialHash(gitCwd,'HEAD',args.projectRoot). It was deliberately deferred from B-6de6 because B-6de6's scope-boundary excluded the escalation advisory path.

## Key Insights
In wrapper-root layouts the git repo root (gitCwd = args.gitCwd ?? args.projectRoot) differs from the metadata/project root. The floor and the producers (quorum_submit at quorum-submit.ts:247/251, autopilot_review_submit via verifier.ts:610) compute and store hashes from gitCwd with metadataRoot = projectRoot. Escalation instead passes projectRoot as the git cwd, so it diffs from the wrong directory: a host_verdict the floor downgrade-accepts (whole-tree materialHash drifted but storyFilesHash still matches) can be read as stale or null by escalation, breaking the intended floor<->escalation equivalence and potentially wrongly staling escalation evidence at the DONE gate (done-oracle.ts:751, machine.ts:639 and :1140) where the floor already receives the resolved gitCwd but escalation does not.

## Solution Tradeoffs
Make evaluateReviewEscalation gitCwd-aware (gitCwd = args.gitCwd ?? args.projectRoot; call currentMaterialHash/currentStoryFilesHash with (gitCwd,'HEAD',args.projectRoot)), then plumb the resolved gitCwd from the DONE-gate callers and the diagnostic handlers so escalation receives the SAME gitCwd as the adjacent floor evaluation; every caller edit stays byte-identical in plain repos (gitCwd == projectRoot). quorum_submit already passes explicit materialHash/storyFilesHash so its internal recompute is bypassed and needs no change. The alternative (only touching the core function) would leave the new param inert in production, so caller plumbing at the gate is required. Wrapper-root regression risk is contained by a dedicated offline equivalence smoke plus the existing review-escalation, review-assurance-floor, and wrapper-root smokes.
