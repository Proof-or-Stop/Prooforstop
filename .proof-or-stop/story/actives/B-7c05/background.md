## Trigger Event
On 2026-07-12, forensic analysis of Claude rollout 019f46ea (turn 40, a 383-call agentic turn in this repo) showed that single large lattice CLI outputs get cache-re-read by every subsequent model call in the turn. One ~10k-token output emitted early in the turn amplified to ~3.8M tokens of ledger-visible volume. Concrete offenders measured in that turn: lattice story_advance printed the full milestone-ledger markdown table three times (~8.4k tokens each), lattice finding_list ~10.2k tokens, lattice help ~10.1k tokens.

## Key Insights
Agent loops pay for every byte of CLI stdout on every later model call in the same turn, so default output size is a multiplicative cost, not an additive one. The expensive part of these outputs (full milestone table columns, full finding descriptions, verbose per-command help prose) is rarely what the driving agent needs at that moment; counts plus next-action is usually enough. A fresh audit on 0.3.185 found even larger silent offenders: story_list defaults to a 365KB JSON dump of all 785 stories and global bug_list to 263KB. The codebase already has a per-handler wantsJson()/format flag convention and a central flag parser, so a brief-by-default switch fits the existing architecture at the handler/renderer seam; cli-engine.ts appendMilestoneStatusAfterMutation() is the single choke point that attaches the milestone table to every mutating command.

## Solution Tradeoffs
Brief-by-default with an explicit full-output flag optimizes for the dominant consumer (agent loops) at the cost of one extra invocation when a human or agent genuinely needs the whole table; a LATTICE_BRIEF_OUTPUT=0 environment escape hatch restores old behavior globally for such workflows. Alternative rejected: keeping verbose defaults and asking agents to remember per-command trim flags does not survive real loops (forensics show they call the bare command). Alternative rejected: trimming the explicit --json/--format=json machine mode, which would break machine consumers; those shapes stay unchanged. Naming constraint: validate already uses --full to mean run-real-machine-tests, so the full-output flag must avoid semantic collision there. Scope guard: this is output rendering hygiene only; gate decisions and gateEvidence semantics are untouched.

## Conversational Texture
The user framed this as agent-loop context hygiene, not gate behavior: reduce the context-fattening CLI outputs that agent loops re-pay on every subsequent model call. They explicitly proposed brief-by-default for story_advance/milestone_status-style giant tables (counts + next action), one-liners for finding_list, the same pattern for other >5k-token default outputs found by audit, JSON modes left alone for machine consumers, and an advisory LATTICE_BRIEF_OUTPUT=0 escape hatch. Tone: pragmatic cost-cutting backed by ledger forensics; they want defaults that are safe to call casually from inside a loop.
