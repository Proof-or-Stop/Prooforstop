## Solution Tradeoffs
Prefer a narrow, duck-typed catch (matching StoryArtifactMissingError by e.name, since the class is intentionally not exported from core/store.ts) over exporting the error class or introducing a new error type, to stay consistent with the existing narrow-catch pattern already used elsewhere in transition-orchestrator.ts for the same error. Prefer routing the smoke test's pass-only-finding assertion through the still-active lattice-review-test-coverage lane rather than inventing a new synthetic lane, since it already carries equivalent pass-only wording coverage in flow-fact-policy.ts.
