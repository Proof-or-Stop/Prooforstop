## Trigger Event
During story B-a745 (the story that added stable validation command identity and the read-only validation_plan planner, DONE on 2026-09-02) three implementers and two reviewer lanes independently reported these duplications: the implementer of B-a745's Story-input-collector item found the quoted-path skip and the unguarded execFileSync in evidence-freshness.ts; the implementer of B-a745's legacy-pin-resolver item found the last private shell parser in done-required-validation.ts after extracting the canonical one; the quality reviewer's finding B-a745:F-014 diffed four workspace resolvers and found the newest lacks the phase-terminal guard. In this draft 'phase-terminal guard' means the check `phase !== 'DONE' && phase !== 'DISCARDED'` that story-query.ts and session.ts apply before reading a linked worktree, so that a story whose worktree has been merged and removed is never resolved as if it were still live. Each was deferred out of B-a745 because evidence-freshness.ts and done-required-validation.ts were protected files in that story's scope contract, and recorded as a session note rather than an in-repository artifact; this draft is the repository record.

## Key Insights
Each of the three is the same class of defect that produced several of B-a745's findings: one fact implemented in two places drifts, and the drift is invisible because each copy is self-consistent. The rename reader is the most dangerous because its failure is silent data loss under a success status; the shell parser duplication is a false-provenance risk between pin identity and DONE-required execution; the resolver duplication is what made B-a745's F-010 fix insufficient after one step, because gitCwd alone did not stop the main checkout's stale checklist and config from being read.

## Solution Tradeoffs
For the reader, parse `git diff --name-status -M -z` (NUL-delimited, which disables C-quoting) and make an unparseable row a hard error rather than a skip; keep the throw on a bad ref but document it as the contract, since B-a745's collector already classifies it correctly and a `catch { return [] }` is exactly the failure to forbid. For the parser, delegate done-required-validation.ts to parseLegacyValidationCommandString and add a fixture asserting all call sites agree on shell-versus-argv for metacharacter, quoted and embedded-space inputs; if the DONE-required path genuinely needs a divergence it becomes an explicit named difference. For resolution, extract one helper returning gitCwd, a workspace-rooted StoryStore and workspace-loaded config with the phase-terminal guard, migrate the four named resolver implementations onto it, and ship an audit fixture that enumerates every resolveGitCwd call site mechanically and classifies it; the wave of migrating the flagged callers is deliberately a separate story scoped by that audit, because three hand-written enumerations in this draft's review history were each wrong.
