## Trigger Event
On 2026-08-16, a stale foreign owner lease blocked continuation of B-d0b8 in TEST from the same canonical worktree, and the user asked the system to finish without repeated confirmation. INIT review disproved two broader premises: StoryOwnerLease.pid identifies the short-lived lattice CLI process that last mutated the lease rather than the long-lived host session, and a live DEV agent could bypass Lattice to edit source or run git even when no lattice CLI PID is alive.

## Key Insights
The mechanically safe automatic case is therefore phase- and class-bounded. It applies only to storyScopedMutating commands in PLAN, REVIEW, or TEST, where source writing is forbidden by the lifecycle. DEV and dangerousMutating remain explicit/manual. Eligibility additionally requires a stale valid lease, canonical same-worktree realpath, same hostname, stable supported session identities for owner and contender, and authoritative ESRCH for the last mutating CLI PID. This proves no owner Lattice command is currently in flight; it does not prove the host session is dead. After an atomic handoff, every later old-session Lattice mutation reads the new owner and is rejected. Story-aware agent_prompt is a separate direct acquire/refresh path: it receives the shared transaction safety but never automatic handoff.

## Solution Tradeoffs
Serialize acquire, refresh, release, explicit takeover, and automatic handoff with a conservative per-story mkdir transaction lock. Under that lock, distinguish absent from malformed state, re-read and revalidate eligibility, and publish leases by unique same-directory temp plus atomic rename. Before publishing a transfer, the unified gate must append a durable Story process-event authorization containing a unique transfer id and both sessions; failure stops the transfer. The existing takeover-count.json remains the single operational counter consumed by convergence-breaker, upgraded to atomic idempotent transfer-id accounting. A transferred lease carries a pending transfer id until that counter is durably reconciled; acquire/refresh/release must reconcile or fail closed before a command can proceed. The durable process-event survives lease release and terminal Story archival, while the runtime counter remains operational state rather than a second audit truth. Explicit --takeover and --forceTakeover keep their existing broader semantics.

The Story deliberately makes no host-session death claim.
