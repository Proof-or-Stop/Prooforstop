## Trigger Event
On 2026-06-19, re-verified in the Orchestrate repo that the LLM usage ledger captures real provider usage ONLY for the claude-code host. The codex and gemini real-subprocess dispatch paths (runCodexRealLeafDispatch / runGeminiRealLeafDispatch -> runBoundedRealLeafDispatch in core/lattice-dispatch.ts around line 1980) carry NO usage-ledger seam: no preflight estimate, no final-usage record. So with LATTICE_USAGE_LEDGER ON, a codex/gemini subprocess run records no token usage.

## Key Insights
The adapters and assemble layer already support these providers: adaptOpenAiUsage (OpenAI/codex usage shape: prompt_tokens / completion_tokens / prompt_tokens_details.cached_tokens) and adaptGeminiUsage (Gemini usageMetadata: promptTokenCount / candidatesTokenCount / cachedContentTokenCount) map to the canonical LedgerUsage, and buildProviderRecord(provider, providerResponse, ...) already dispatches 'openai'|'gemini' internally via adaptUsageFor. Two facts block the wiring: (1) the ledger seam (preflight + final) exists only in runClaudeCodeRealLeafDispatch, not in the shared codex/gemini runBoundedRealLeafDispatch; (2) the codex/gemini bounded runners (runBoundedCodexProvider / runBoundedGeminiProvider) deliberately surface stdout as digest + byte-count ONLY -- a stated security invariant (raw output is never surfaced so a provider transcript can neither leak credentials nor be promoted into gate evidence). So no raw codex/gemini stdout reaches the dispatch layer to be parsed.

## Solution Tradeoffs
The fix is a three-layer vertical that RESPECTS the raw-never-surfaced invariant. (1) The bounded provider runners extract ONLY the token-count usage object from their own stdout (analogous to the existing extractCodexModel) and surface it as a provider-neutral reportedUsage field on ProviderExecResult -- token counts are numbers, not transcript text, so the invariant holds. (2) dispatch-usage.ts gains a canonical per-provider final entry point that routes through buildProviderRecord('openai'|'gemini', reportedUsage, ...), keeping the existing claude/anthropic recordDispatchFinal and parseClaudeCliOutput byte-identical. (3) runBoundedRealLeafDispatch wires the seam (preflight estimate + postflight final + supersede), all fail-open, with the LATTICE_USAGE_LEDGER=OFF path byte-identical. Budget-guard parity for codex/gemini is deferred (a separate fail-closed concern); this story is usage CAPTURE only.
