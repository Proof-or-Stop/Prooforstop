## Trigger Event
Follow-on to story B-ec67 (the tool-executed evidence-receipts enforcement floor), which shipped on 2026-07-26 after cross-host review found three write-path bypasses. That story pins a (command,selector) on the intent and makes the evidence-write handlers execute it; it also demotes a stale-refreshed receipt so it cannot launder. It deliberately deferred the ergonomic command, the early-warning hook, and full re-execution of stale evidence to this follow-on, so the enforcement floor stayed a reviewable unit.

## Key Insights
The strongest guarantee is not validation but making the correct action the path of least resistance: a first-class verification_run command that resolves the intent and executes the pinned verifier means a caller never hand-authors a pass command, so the class of false-command mistakes (the F-045/F-049/F-050/F-061 family) has no ergonomic on-ramp. The stale-evidence refresh must not merely demote a receipt when material changes — it should re-run the pinned command and re-issue a real receipt, so a refreshed row is genuinely re-proven, not just invalidated. The PreToolUse hook is a seatbelt, not the floor: because the enforcement-floor handler already refuses a mismatch, a fail-open early-warning hook that blocks with a teaching message before the write runs adds signal without being load-bearing; it must be gated on each host's real emitted shell-tool name via an e2e test or it silently never fires.

## Solution Tradeoffs
Adding verification_run as a new command (rather than only tightening verification_evidence_add) makes the tool-executed path the obvious one; ideally the add path stops accepting a caller command for automated proof entirely, but that migration is staged so in-flight callers are not hard-broken. Re-execution in the stale-evidence refresh is chosen over the interim demote-only behavior because a demoted row blocks until manually re-proven, whereas re-execution keeps a genuinely-still-passing row green automatically. The PreToolUse hook is fail-open by deliberate choice: the handler is the real floor, so a hook failure must never block legitimate work.

## Conversational Texture
The operator wants enforcement moved out of memory and into the tooling, with the correct action made easiest and the incorrect one impossible; this story delivers the ergonomic on-ramp and the early-warning belt on top of the already-shipped floor, and closes the refresh loop so a re-attested row is really re-run rather than trusted.
