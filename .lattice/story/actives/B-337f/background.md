## Solution Tradeoffs
Semi-synthetic workspaces are generated from in-repo templates (plain string templates inside the generator, parameterized by seed-derived values), not copies of real repo files — copying real docs would re-import the leakage the plan forbids and make fixtures drift with the repo. Oracles are pure Node functions over the workspace directory (the recovery-runner ground-truth.mjs pattern) so M4 can invoke them without a live reviewer. Held-out trap classes are authored in this story as fixture templates only (their defining property — no corresponding lesson in the runtime memory store — is validated by the corpus selfcheck grepping the store snapshot for their signature phrases at generation time is NOT possible against a live store; instead the selfcheck asserts the held-out classes are disjoint from the six in-store class names and documents that the M6 pilot's protocol freeze must verify absence against the frozen memory snapshot). Scale: the generator takes counts per class as parameters (the powered N comes from M5/M6 later); the corpus selfcheck runs on a small deterministic sample. English-only artifacts.
