## Key Insights
The wrapper-root layout means metadataRoot (project root holding lattice.config.json) is NOT the git repo — the git repo is a configured `gitRoot` subdir. The `resolveGitCwd` helper at packages/main/src/core/story-signed-workspace-resolution.ts:195 returns the correct cwd in both layouts (gitRoot subdir for wrapper-root, projectRoot for plain repos). 193 `execFileSync('git'|spawnSync('git'|execSync('git'` call sites exist across 88 TypeScript source files; existing rerouted-site smokes (gitroot-cwd-routing-smoke, bare-gate-gitroot-cwd-smoke) cover the SPECIFIC sites that prior P1 fixes (B-1637, B-e791, B-0740, B-2856) reached, but they do not prevent a NEW unrouted call site from being added — exactly how the defect class kept recurring story-after-story. The repo also has 3 ad-hoc git helpers (lab.ts runGit, cli-engine.ts runGitNoThrow, declared-artifact-commit-check.ts runGit) that internally take a cwd from their caller; they themselves are wrappers but their callers can still pass a bare projectRoot. The fix is single-direction: make resolveGitCwd the choke-point, audit all 193 callers, reroute the unrouted, and codify the contract via a grep-based smoke test.

## Solution Tradeoffs
Choke-point + grep-contract over a more invasive structural refactor: keep `runGit` style wrappers (they're useful for stdout/exit-code handling), but require their cwd argument to come from resolveGitCwd. The grep contract is cheap, fast, and forces every new git call site to go through the helper — eliminating the whack-a-mole pattern. Alternative considered: eslint custom rule. Rejected — eslint integration cost is higher and the team already prefers smoke-test contracts (per existing pattern). Out of scope: rewriting the smoke-runner infrastructure (#2), changing resolveGitCwd's signature, and changing wrapper-root storage semantics.
