# B-235e Execution Plan

## Outcome

Five active reviewer roles use independently reversible modular Prompt Envelopes. Trusted full and mechanically eligible incremental dispatch remain authority-bound, replay reports honest per-role quality and token results, and retired channel remains excluded.

## CHK-001 — Migrate the five active reviewer role prompts behind independent rollback flags

- Freeze content-addressed legacy bodies before changing canonical modular bodies.
- Add a mode-aware role-body resolver so legacy-full-context restores exact bytes and full-envelope selects the modular body.
- Treat legacy bodies, modular bodies, and their approval records as immutable digest-bound repository artifacts committed through normal Story git flow; do not introduce a mutable baseline writer. If a mutable shared writer is later added, it must use the canonical main write lock.
- Extract the repeated runtime guide from concept, quality, behavior, and docs; compact test-coverage process boilerplate while preserving every role-specific lens.
- Add five independent rollout entries; never add retired channel.
- Regenerate Claude and Codex mirrors from the package canonical source.
- Verify all mixed rollout combinations, host identity binding, active roster, compatibility behavior, exact rollback, immutable baseline identity, and role substitution resistance.

## CHK-002 — Assemble trusted full or eligible incremental reviewer Prompt Envelopes

- Reuse review_run_start as the only evidence-capable assembly point.
- Feed the mode-aware role body into existing full or conditional assembly; do not add caller-controlled incremental switches.
- Update both handler-time assembly and core review-run gate reconstruction so the exact modular or legacy body identity is verified by consumers.
- Make dispatch language mode-neutral, bind host/body identity, and expose role, context mode, stable selection reason, and budget observations.
- Preserve authoritative read-through and explicit reviewer-requested-full behavior.
- Test source, docs, public API, schema, authority, scope, policy, freshness, signature, digest, wrong-lane, replay, and concurrent snapshot drift as full-review triggers.

## CHK-003 — Prove per-role quality and input reduction with preregistered replay

- Keep the Story 3 frozen corpus unchanged and add a versioned B-235e role-aware campaign.
- Pin five roles, legacy/modular/full/incremental arms, exact prompt snapshots and digests, material/model/tools/order, at least three applicable repetitions, and an independent adjudication digest.
- Report context-only tokens separately from whole assembled prompt and from provider/cache usage.
- Require critical seeded detection and no confirmed systematic high miss; otherwise report INCONCLUSIVE per role.
- Enforce denominator, arm symmetry, role identity, tamper, cherry-pick, cache accounting, command-misuse, false-positive, and production-evidence isolation checks.

## CHK-004 — Preserve reviewer authority and verify rollback, compatibility, and process contracts

- Keep all reviewer pass and finding writes behind current signed ReviewRun and lane authority.
- Preserve the governing binding-race rule: a fresh valid non-latest same-round PASS may remain admissible, while findings use kind-aware stale-run handling; never replace this with a blanket latest-run rule.
- Prove main, implementer, wrong lane, compatibility, and retired evidence cannot gain active gate credit.
- Bind per-role baseline diff approval to the exact immutable legacy, modular, Role Contract, and host-render digests; update all three canonical baseline artifacts.
- Test old envelope-less passes only as original-round legacy-full-context and test every mixed rollback state.
- Update process-fact registry and verifier, the canonical decision plan, host-run usage documentation, CLI help where applicable, and Claude/Codex adapter verification.
- Run build, focused smokes, original Story 3 selfcheck, Story 5 campaign selfcheck, process-fact verifier, baseline verifier, verify_codex, and full validation before DONE.

## Ordering and stop conditions

Implement CHK-001 through CHK-004 in order. Correctness and authority failures block progress. A budget target miss records a violation or INCONCLUSIVE result but never weakens a required full review. Any proposal to migrate complex roles, reactivate channel, or enable budget enforcement stops as scope expansion for Story 6, Story 7, or the conditional follow-up.
