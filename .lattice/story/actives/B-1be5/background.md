## Trigger Event
On 2026-07-12, forensics on story B-8038 (created 10:07Z, DONE 12:30Z the same day) showed its whole lifecycle ran on Codex Desktop: one 12-hour driver thread (rollout 019f53e2, 209M cumulative input) plus ten worker/fork threads burned ~0.92B real input tokens in one day, 98.4% cache reads, bypassing the host_run budget caps and writing zero usage-ledger rows. The user then asked for the root fix in this order: after the B-623a push-based burn alarm (DONE, v0.3.192), bind the review gates to the ledger so unmetered execution cannot produce accepted quorum evidence.

## Key Insights
The existing guardrails (host_run per-dispatch budget caps, usage-ledger rows, reviewer scan budgets) are all callee-side: they apply only to processes lattice launches. Proof-or-Stop gates verify evidence CONTENT (hashes, signatures, freshness) but never execution PROVENANCE, so a desktop agent-team verdict and a metered host_run verdict look identical to the gate. B-70e9 already writes preflight+final usage-ledger rows bound to storyId, agentType, phase, provider, reviewRunId->threadId, and lane->subagentId - the corroboration data exists; nothing consumes it. Prose rules do not hold (dev-memory fa1777b: agents silently deviate from scan mandates), so the check must be mechanical.

## Solution Tradeoffs
Bind at the choke points that already exist - quorum_submit (writer) and the DONE-side review escalation evaluation (consumer) - rather than inventing a new evidence type or trying to gate lane reviewer passes: lane reviewers are in-session subagents that legitimately never touch host_run, so gating them would break every story; only the evidence class claiming INDEPENDENT HOST runs is bindable. A staged shadow->warn->enforce rollout (config-driven, shadow default) mirrors the proven candidate-spec-routing rollout shape so existing stories cannot be bricked by a hard cutover; enforce mode is opt-in per project config until confidence is built. Corroboration uses the ledger rows lattice itself wrote (same trust root as the gate), not host transcript stores (which are NON-AUTHORITATIVE estimates per B-70e9).

## Conversational Texture
The user framed this as the enforcement layer of a three-part program: alarm (B-623a, detection), ledger binding (this story, making unmetered execution unable to pass the gate), and a later command-output tripwire (making the burning session see its own counter). The user cares that the gate distinction is honest - metered host_run lanes cost 10-50x less than desktop agent-teams and leave an audit trail - and that the rollout does not break the many stories currently in flight, hence shadow-first with an explicit config switch to enforce.
