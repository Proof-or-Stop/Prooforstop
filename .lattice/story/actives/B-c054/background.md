## Trigger Event
On 2026-07-25 the RED-evidence subsystem decision spec (story B-7dfa) is DONE and merged to main at docs/requirements/decisions/red-evidence-subsystem-spec.md. This story implements Workstream 2 area 1 of that spec: §0.4 (CANON, nullability, self-omitting recordDigest), §0.6 (assurance tier), §1.2 (policy table, registries, argv/env/executable resolution, exhaustive snapshot, per-key defaults), and §1.12 (hard safety floors, clamp-REJECT, invarianceExcludePaths). It is the foundation every later W2 story digests and resolves policy through; nothing else can land until CANON and the policy resolver exist.

## Key Insights
No existing canonicalizer can serve as CANON, and this must be proven mechanically rather than asserted: digestCanonicalJson (packages/main/src/core/digest.ts:40) sorts keys with a.localeCompare(b) at :27, which reorders {"B":1,"a":2} differently from RFC 8785's UTF-16 code-unit order; and canonicalJsonForSigning (packages/main/src/core/authority-signing.ts:79) via normalizeSigningJson at :65 maps JSON null to undefined, dropping a priorRecordDigest: null field that CANON must preserve. The spec's §1.2 policySnapshot is an exhaustive fourteen-key set with enumerated defaults (the full 1..255 exit-code array, two default adapters, one default profile) whose policyDigest must equal a frozen constant so any fudged default fails. pinnedPath is required-with-no-default and host-specific, so a redEvidence block must NOT be committed to lattice.config.json — every smoke resolves policy from a fixture config in a temp project. The §1.12 floors CLAMP-REJECT rather than silently clamp: minMatcherLen below 4, minMatcherEntropyBits below 12, maxMatchers above 32, maxMatcherLen above 4096, runTimeoutMs out of range each reject with one distinct named diagnostic.

## Solution Tradeoffs
The critic panel flagged that terminating at doctor with a byte-identical-output requirement would make the consumer dead code — the doctor line could never render because no redEvidence block is committed. The resolution, adopted here: doctor is NOT a gate, so the health check ALWAYS emits one line (the resolved policyDigest, or the fail-closed diagnostic when a fixture-resolved policy is invalid), and the checklist proves doctor's EXIT CODE is unchanged plus no gate evidence is written plus proofstory_gate_check output is byte-identical — not that doctor stdout is frozen. The alternative of committing a redEvidence block to exercise the line was rejected because pinnedPath would bind the repo to one host layout and fail closed on other hosts and CI. CANON is a new leaf rather than a reuse because the two differential proofs show every existing helper is wrong for it; reusing one would silently corrupt every downstream digest.
