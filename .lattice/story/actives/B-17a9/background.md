## Trigger Event
The Experience Layer phase 3.5 analysis (2026-06-18, Work/lattice-Paper/) LLM-backfilled real semantic signatures over 695 historical findings (164 canonical area|failureMode classes) and proved the experience substrate is learnable (held-out temporal split: 62% of future findings repeat a known specific class). But the LIVE findings still carry almost no signatureTag (~22 of 695), so on main learning_scan derives near-empty signals and learning_effectiveness honestly reports zeros. This story persists the proven signatures so the apparatus runs on real data.

## Key Insights
finding_add already stores signatureTag + signatureTagSource as AUDIT-ONLY fields EXCLUDED from the finding _hash / signFinding (B-4f46 + B-5d48 phase 3.2; finding.ts ~line 312 attaches them AFTER _hash). store.writeFindings(storyId,data) is the write port. SignatureTagSource is currently 'auto'|'confirmed' (experience-layer-types.ts:81); this story adds 'backfill'. The command reads a committed { findingId -> signature } map (no LLM at runtime -- auditable + deterministic) and fills empty tags only. Because signatureTag is _hash-excluded, writing it to ~190 stories' findings.json must NOT change any finding _hash -- the single most important safety property (a mass write that moved _hash would break the REVIEW->TEST findings gate across those stories).

## Solution Tradeoffs
The command is a WRITING L2 experience-layer command (like signature_registry_set; registered incl. PROCESS_FACT_LEVELS; NOT read-only). Dry-run is the default; --apply performs writes; only empty signatureTags are filled (never overwrite confirmed; auto only with --overwriteAuto). The actual mass-apply against live findings is an OPERATION run after this story is DONE+merged (the story itself builds + hermetically tests the command via dry-run + temp-store smoke); this keeps the reviewed diff small and the mass write out of the story's own diff. Rollback = revert / a clear-backfill mode; _hash never moves so no gate state is perturbed.
