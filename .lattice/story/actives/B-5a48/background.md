## Trigger Event
On 2026-06-20 (after B-37b3 made the finding-signals cache reachable from worktrees and B-1a91 made it auto-refresh on every DONE merge), the operator asked to wire the Experience Layer A/B-gated hints into the REVIEW loop. Today the advisory experience hints are computed + rendered ONLY inside story_review's `_reviewPrompt` (PLAN-phase advisory channel, A/B-gated via hint-mode.ts, firing experience_hint_surfaced). But the REVIEW-phase lane reviewers (lattice-review-concept/quality/test-coverage) are launched by the main agent with hand-written prompts that BYPASS `_reviewPrompt`, so the ON arm never reaches the reviewers and REVIEW rounds emit ZERO experience_hint_surfaced events — learning_effectiveness ON/OFF cannot accrue toward MIN_ARM_N=20.

## Key Insights
A design workflow (4 parallel subsystem reads + 3-angle design panel + judge synthesis, all verified against code) chose a HYBRID: surface the SAME rendered+A/B-gated hints in the REVIEW reviewer-launch guidance text the agent already reads (buildNextSteps in handlers/transition-effects.ts), AND extract a single shared leaf core/experience-hint-surface.ts (surfaceExperienceHints) so the firing+dedup+arm logic lives in ONE place (no drift between the PLAN site and the new REVIEW site). VERIFIED: transition-orchestrator.ts persists story.currentReviewRound via writeStory BEFORE buildNextSteps runs, so the REVIEW dedup key equals the ISO round stamp story_review uses; PLAN keys on `plan:<phase>` and REVIEW keys on the ISO currentReviewRound → DISJOINT namespaces → structurally impossible to double-count across phases, while same-round repeats collapse via the identical readActivityLogTail dedup scan. The event payload {timestamp,event,storyId,reviewRound,hintMode,hintIds} is byte-shape-identical to today, so learning-effectiveness reads the new REVIEW events unchanged. NET NEW VALUE: REVIEW rounds, which emit zero experience_hint_surfaced today, now accrue toward BOTH arms (hintMode distinguishes; full hintIds on both = lossless).

## Solution Tradeoffs
CHOSEN: next-steps REVIEW surface + shared firing leaf, NO new command (zero registration burden: no command-policy / process-fact-levels / READ_ONLY_COMMANDS / registry / catalog edits; lifecycle-registry-contract stays green untouched). The new smoke is auto-discovered by run-all-smokes. REJECTED: (a) a new read-only review_hints command (5-surface + contract tax, and the agent must REMEMBER to run it — less forceful than putting hints in the text the agent already reads); (b) injecting hints into review-run.ts / the signed reviewer prompt (would risk the resolveReviewPromptHash invariant). DEFERRED by operator decision (2026-06-20): also injecting into the per-item `lattice dispatch --itemId` path (story-dispatch.ts buildItemPrompt) — the main agent launches lane reviewers via the Agent tool, not via lattice dispatch, so the next-steps surface is the relevant vector; the dispatch path is a separate, additive surface, not in scope. Operator also chose: OFF arm appends NOTHING (REVIEW guidance byte-identical to today → honest A/B contrast, no placeholder); accrual is per REVIEW ROUND (consistent with story_review's existing dedup semantics).

## ADVISORY-ONLY INVARIANTS (must hold)
review-run.ts and core/review-run.ts:resolveReviewPromptHash are NOT in the change set — ON vs OFF arm reviewer prompt hash byte-identical (hint content never enters the signed prompt). The new transition-effects block is append-only to the returned guidance STRING inside try/catch (never blocks/alters the transition; no gate reads it). The story-review.ts refactor is behavior-preserving (golden byte-equality on _reviewPrompt + event payload). OFF arm appends nothing → REVIEW next-steps text byte-identical to today.
