## Trigger Event
On 2026-07-13, story B-f458 burned ~14 hours (08:20Z-22:36Z) in a non-converging death loop with zero mechanical circuit breaker. Forensics archive proofbound/tmp/bf458-forensics-2026-07-14/ (activity.jsonl, 926 events) records 89 story_advance events (a healthy lifecycle needs 6-10; 41x DEV->REVIEW + 39x REVIEW->DEV is pure ping-pong), 131 review_run_start against only 31 review_pass_set (78% churn; after 14Z / 16:00 local, 8 hours produced ~4 passes), and 65 lease-takeover events plus 238 takeover-flagged commands (three concurrent threads at 09:17Z fighting over the owner lease). The framework happily processed all of it.

## Key Insights
The framework has soft signals but no hard brake. core/review-convergence.ts (B-cfdd) derives a stall advisory but is documented to NEVER block a transition; core/anti-stall.ts (B-ef9c) only renders retry/fix/discard text; core/usage-burn-alert.ts (B-623a) watches host-session token burn, not the story lifecycle, and is advisory-only. core/story-owner-lease.ts (B-c55d) enforces single-owner at a point in time but never counts takeover frequency, so 65 forceTakeover overrides each passed as a deliberate human override. Nothing counts global advance count, review pass-rate, or takeover frequency to actually stop a runaway story.

## Solution Tradeoffs
A hard human-ack on every stall would kill unattended autonomous development, so the breaker is graduated. Healthy stories (6-10 advances, converging) never trip. A pathological signature (advance far over normal with no net progress / same gate failing the same reason twice / takeover storm) hard-stops the current loop and auto-recovers ONCE (reset the window baseline, surface the authoritative next action); only a re-trip after that automated attempt escalates to a frozen state cleared by an explicit human ack command that refuses under autopilot / non-interactive mode. Counters are derived read-only from story.events (same approach as review-convergence.ts); thresholds are env-tunable module constants mirroring the B-623a BURN_ALERT_ENV pattern. Blocker-hint specifics (milestone_ledger_set) and review_pass_set writer-identity are OUT of scope, owned by concurrent work.

Their own manual recovery discipline - refusing to be the second participant in a takeover loop, self-imposing a round budget, reading diagnostics before acting - is exactly what this story mechanizes into the framework so that the 14-hour unattended burn cannot recur.
