## Trigger Event
On 2026-06-19 the operator directed that Google's Gemini CLI semantics are deprecated in favor of the new Antigravity CLI (command `agy`, installed at ~/.local/bin/agy). A bounded probe (`agy --print`) confirmed: agy is an agentic coding CLI (Cascade/Antigravity lineage, product=antigravity) that authenticates via keyring and calls Google's `.../v1internal:streamGenerateContent` under the hood, but its stdout returns ONLY the response text and its --log-file (INFO) does NOT surface per-call token usage. This story migrates the in-tree `gemini` provider to `antigravity`. It follows B-b1f4 (which added primaryReportedTotal/primaryKnown for codex/gemini token visibility).

## Key Insights
The current `gemini` provider lives in packages/main/src/providers/gemini-cli.ts (GEMINI_CLI_BINARY='gemini', geminiCliAvailable, runBoundedGeminiProvider, extractGeminiUsage/extractGeminiModel) and is wired into the live-dispatch path (lattice-dispatch.ts runGeminiRealLeafDispatch, BoundedProviderName 'gemini', PROVIDER_BINARY) and the planned-steps executor (planned-steps-executor.ts imports geminiCliAvailable/runBoundedGeminiProvider/GEMINI_CLI_BINARY). The usage adapter packages/main/src/core/usage-ledger/adapters/gemini.ts (adaptGeminiUsage) maps Gemini-API usageMetadata (promptTokenCount/candidatesTokenCount/cachedContentTokenCount) and is dispatched from assemble.ts adaptUsageFor (ProviderName 'anthropic'|'openai'|'gemini', case 'gemini'). A probe of agy's per-conversation SQLite trajectory store (~/.gemini/antigravity-cli/conversations/*.db) showed the blobs are undocumented protobuf carrying model CONFIG (context window 200000, max output 8192) and the raw transcript/system-prompt, but NO cleanly identifiable per-call usageMetadata; extracting a token count would require guessing varint fields (inference) and reading raw content — both forbidden by usage-ledger invariants. Therefore agy provides no usable token usage at its surface.

## Solution Tradeoffs
Chosen: hard in-place rename gemini->antigravity (no backward-compat alias) with binary gemini->agy and agy's `--print` interface; usage recorded as source=unavailable (model label captured best-effort from the --log-file, never token counts). The Gemini-API usage adapter (adapters/gemini.ts) is DELETED outright (along with the assemble.ts 'gemini' ProviderName branch) because antigravity never produces provider-reported usage, so the adapter is dead — recordDispatchFinalForProvider already writes an unavailable final when no reportedUsage is present. Rejected: keeping a gemini->agy alias (operator wants the old semantics gone); digging the trajectory store for usage (proven infeasible — inference + raw-surface violations); inventing cacheCreation/token zeros (violates no-inference). The three usage-ledger invariants stay intact: zero-cross-module-import, raw-never-surfaced, never-infer-unreported. Token capture for antigravity is explicitly out of scope (deferred until agy exposes usage on a stable, documented surface).

## Conversational Texture
The operator cares that the tool actually used (Antigravity / agy) is what the system dispatches and names, and that the audit ledger stays honest — recording that an antigravity call happened (with its model) without fabricating token numbers it cannot observe. Acceptance focuses on: dispatch routes --host=antigravity to the `agy` binary; an antigravity call writes a provider.name=antigravity ledger final with source=unavailable; the deleted gemini adapter leaves no provider-semantic residue; and the existing suite (renamed) stays green.
