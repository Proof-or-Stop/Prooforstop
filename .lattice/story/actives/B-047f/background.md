## Key Insights
The rev-2 plan's S13 milestone table names what each milestone reuses and its exit criteria. M0: reuse the sha256 hash-checked mechanics proven in experiments/recovery-runner/checks.mjs and live-engine.mjs plus the pre-registration discipline of docs/requirements/decisions/lattice-experiment-protocol.md; exit = protocol.json validates, no task runs without a protocol hash, memory-snapshot hash frozen. M2: reuse the xmur3/mulberry32 string-seeded PRNG + Fisher-Yates seededShuffle pattern from experiments/recovery-runner/run-driver.mjs and the append-only jsonl sidecar pattern; exit = same seed reproduces the run order, ledger immutable once the first score record exists. M5: reuse the statistical primitives already exported by experiments/recovery-runner/analyze.mjs (two-proportion machinery, Wilson CI, bootstrap, Benjamini-Hochberg); exit = report shows planned N per population, assumptions, and detectable effect. The plan's S7 fixes anchor the calculator's expected values, independently verified three times during the B-36fd review (Claude quality lane, Codex host-2 twice): pooled two-proportion z at alpha 0.05 / power 0.80 gives ~294 per arm at baseline 0.30 / MDE 0.10 (reduction direction: treatment = baseline - MDE), ~62 at baseline 0.625 / MDE 0.25 (the in-band maximum), corner values 27 (0.5/0.35) and 58 (0.5/0.25); the pilot freeze rule is >=15 control-arm fault-task runs, freeze N at the Wilson 95% CI lower bound, extend the pilot if the CI is wider than 0.30. M2 must consume M0's protocol hash (a ledger refuses to build without a frozen protocol), which mechanically enforces M0's no-task-without-hash exit criterion.

## Solution Tradeoffs
All three tools are plain Node .mjs scripts under experiments/experience-ablation/ with hermetic selfchecks, mirroring the committed recovery-runner layout — NOT product code, NOT gate code, and not importing from packages/*/src (the calculator re-implements the small closed-form formulas rather than importing analyze.mjs internals, keeping the experiment directory self-contained the way recovery-runner is; the reuse is of the proven pattern and constants, with selfcheck values cross-checked against the plan's reviewed numbers). Runtime experiment artifacts write under .lattice/experiments/experience-ablation/<experimentId>/ exactly as the plan's S12 prescribes (protocol.json, fixture-manifest.jsonl, pair-ledger.jsonl, run-order-seed.json, memory-snapshot-hash.json). Immutability is enforced by refusing writes when score-records.jsonl exists rather than by filesystem permissions (portable, testable). The fixture manifest schema accepts fixtures that do not exist yet (M1 builds them later); S1 only guarantees the manifest/ledger/order machinery.
