## Trigger Event
On 2026-06-19, and earlier on B-59c7 and B-12d7, review rounds were lost because story code was committed AFTER review_run_start captured the run's headHash/materialHash: the next finding_add / review_pass_set was rejected as stale, forcing a story_advance back to DEV and a full re-run of every reviewer lane. There is no clean-tree check at DEV->REVIEW or at review_run_start today.

## Key Insights
REVIEW evidence binds to the review run's headHash + materialHash captured at review_run_start; the only soundness guard is checkEvidenceFreshnessForGit at evidence-write time, so a mid-review commit silently invalidates work already recorded. The DONE gate already has a dirty-worktree precedent (done-oracle.ts evaluateDirtyGitStatus) using a shared classifier classifyGitStatusRows + DIRTY_GATE_POLICY (dirty-gate-policy.ts). Per that policy BOTH material_source_changes AND fixture_changes are BLOCKING, while lattice_metadata_changes / runtime_artifact_changes / declared_artifact_changes are non-blocking. IMPORTANT: the git-status reader readGitStatusLines is currently a PRIVATE function in done-oracle.ts, so it must first be exported or extracted into a small shared helper before review_run_start can reuse the same read+classify path.

## Solution Tradeoffs
Add a fail-fast preflight in review_run_start that reuses the DONE gate's evaluation directly (evaluateDirtyGate over classifyGitStatusRows) and refuses when it reports ANY BLOCKING category (material-source or fixture changes); the materialHash-excluded non-blocking categories (lattice metadata, runtime artifacts, declared artifacts) pass. Reuse the verdict rather than re-enumerating categories so the preflight can never diverge from the DONE gate. Honest framing: this is a fail-fast UX convenience, NOT a new soundness gate -- evidence-freshness at write time remains the real guard, and the preflight cannot catch the post-snapshot commit case (a commit made AFTER review_run_start). Insertion point is review_run_start (tightest timing) rather than story_advance DEV->REVIEW. The only non-trivial work is exporting/extracting the private readGitStatusLines without changing the DONE gate's behavior.
