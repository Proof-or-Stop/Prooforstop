## Trigger Event
On 2026-07-23 story B-956f and on 2026-07-24 story B-bf52 both hit a blocking OUT_OF_SCOPE scope violation on .lattice/story/actives/<id>/acceptance-basis.json immediately after running the PLAN-phase acceptance_basis_generate step. The classifier reported category=unknown rule=out_of_scope detail="No lifecycle/runtime registry entry and no scope-contract path pattern matched", and each story had to run scope_contract_acknowledge by hand on framework-generated metadata to proceed.

## Key Insights
classifyLifecycleArtifact (packages/main/src/core/lifecycle-registry.ts) only recognizes top-level story-dir files whose basename is in the closed set LATTICE_LIFECYCLE_ARTIFACT_FILENAMES. Live repro against dist confirms five StoryStore-written filenames are missing: acceptance-basis.json, pre-review-check.json, topology-critic-receipt.json, topology-exclusion-approvals.json, authority-receipt-refs.json. The first four were added by the acceptance-topology work (commits bff1a4c277, 78a483a4d6) without registry updates; the fifth dates to the initial export and has no live writer today. B-12a1 previously fixed the same class by hand-adding ten intent artifact filenames, which shows one-off patching does not prevent recurrence.

## Solution Tradeoffs
Option A: add only acceptance-basis.json — unblocks the reported symptom but leaves four known-missing filenames and the regression class open. Option B: add all five missing filenames plus a coverage-invariant smoke that derives the set of top-level story artifact filenames StoryStore writes and asserts registry coverage — slightly more work, closes the class mechanically. Option C: make the classifier open (allow any *.json under a story dir) — rejected; the closed set is a deliberate narrow-trust policy from B-b9d0 and opening it would weaken scope enforcement. Chosen: B.
