## Trigger Event
During the 2026-06-16 full-framework review (same session that opened story B-94ae for the CLAUDE.md:77 fix), the user asked for P3's second half: make the docs-drift gate also scan CLAUDE.md itself so the main doc cannot lie again. Investigation of validate-docs-drift.ts confirmed the gate already reads CLAUDE.md but only checks lattice command-name alignment with the registry.

## Key Insights
The .Codex/hooks contradiction survived because the docs-drift gate has no path/managed-asset awareness — it only diffs command names. The building blocks already exist and are NOT reused by the gate: core/audit-scan.ts exports scanPathDrift (line 214) and scanFlagDrift (line 144), currently consumed only by handlers/audit.ts; and core/managed-assets.ts is the source of truth for what lattice init generates (.claude/hooks, the Codex adapter hooks, etc.). Wiring these into the CLAUDE.md gate closes the class of bug where the doc claims a framework-generated path is forbidden or claims a non-existent path exists. The specific P3 shape is a managed-asset contradiction: doc says 'do not create <X>' but <X> is in the managed-asset registry.

## Solution Tradeoffs
Approach A (chosen): reuse scanPathDrift + the managed-asset registry inside validate-docs-drift.ts, adding (1) a path-existence check for paths CLAUDE.md references and (2) a managed-asset contradiction check (forbidden/absent claims about assets the framework generates), keeping the command-name scan unchanged and additive. Approach B (re-implement path scanning inside the gate) was rejected as duplicating audit-scan and risking drift between the two scanners. Approach C (general NL contradiction detection) was rejected as unbounded; the mechanical, registry-backed check is sufficient for the P3 class. Risk: false positives on legitimately-deleted or example paths — mitigated by an allowlist seam mirroring the existing 'do not build this CLI' command allowlist already in validate-docs-drift.ts.

## Conversational Texture
The user split P3 into two stories on purpose: B-94ae fixes the current lie in the doc; this story prevents the next one by giving the gate teeth. They chose to open this in parallel now. The framing throughout was 'make the framework hold itself to the same docs-drift standard it enforces on reviewer/process docs' — eliminating the 'framework does not follow its own rules' trust cost.
