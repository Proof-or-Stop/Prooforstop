## Key Insights
Reviewer verdicts record their bound headHash (core/review-run.ts captureReviewRunSnapshot); git exposes per-file blob hashes and a diff between two commits is available (core/evidence-freshness.ts changedFilesBetween). So the incremental diff since a reviewer last passed is computable with no new persistence. Because round 2+ already only needs >=1 valid receipt, an operator can today legally re-run just the reviewer(s) whose scope changed -- the missing pieces are (a) operators do not know this, and (b) no signal shows which reviewers' scope changed. This story supplies both without touching the gate, so under-review risk is unchanged from today (still an operator judgement, never a framework skip).

## Solution Tradeoffs
Merged option 2 (chosen): incremental-context helper + round-2+ informed targeted re-review guidance; gate unchanged; zero framework-side skipping. Pros: real cost cut on both round-1 re-runs and operator-chosen round-2+ re-runs, plus it unlocks the already-legal round-2+ targeted path with information support; no gate/binding change. Cons: targeted re-review remains an operator judgement (same under-review responsibility as today). Rejected B-skip: framework carries forward unaffected reviewers -- larger automation but irreducible under-review risk because an LLM reviewer's true dependency set is not statically provable. Rejected do-nothing: leaves each re-run doing redundant full analysis and keeps the round-2+ leniency hidden.
