## Trigger Event
On 2026-06-20, verifying the Experience Layer found the finding-signals cache (.lattice/learning/finding-signals.json) is updated ONLY by an explicit `lattice learning_scan` (config.ts:196 calls it an "out-of-band maintenance WRITER"); code-confirmed there is NO automatic trigger on DONE / finding mutation / hook / cron / CI. So the cache went stale (last derive 6-19 01:45 until a manual refresh on 6-20), and accumulated experience from completed stories does not surface until someone remembers to re-scan. B-37b3 just fixed cache REACHABILITY from worktrees; this story fixes cache FRESHNESS.

## Key Insights
applyDoneMergeEffects (handlers/done-effects.ts ~890-896) already runs two automatic post-merge effects on the main write-lock: bumpVersionOnDoneMerge (gated on material-code change) and runDoneMainPackageBuildAfterMerge (auto-rebuild dist). The finding-signals cache re-derivation (deriveFindingSignalsFromStore(store, { projectRoot }) in core/finding-signals.ts, which persists via learning-store writeFindingSignals → resolveLearningRoot → canonical MAIN cache, post-B-37b3) is the natural third effect: cheap (reads findings via store ports, writes one JSON), advisory-only, never read by any gate. Running it on every DONE merge folds the just-completed story’s resolved findings into the cache so experience accumulates automatically with every story.

## Solution Tradeoffs
Add a never-throw, advisory finding-signals re-derive to applyDoneMergeEffects AFTER the merge (alongside auto-bump/auto-rebuild), appending a status line to the merge report. Run it on EVERY DONE merge (NOT gated on material-code) because findings accrue per-story regardless of code change (e.g. docs/doc-code-mismatch findings), and the re-derive is cheap. It MUST never break or block the DONE merge (try/catch, advisory line on failure) — the cache is non-gate. Write to the canonical MAIN cache (rely on B-37b3 resolveLearningRoot). REJECT a cron/CI schedule (main cron unreliable; misses the just-merged story) and REJECT a pre-REVIEW agent step (depends on the agent remembering) — the DONE-merge hook is the reliable, same-mechanism-as-auto-bump place.

The operator approved wiring learning_scan-equivalent auto-refresh into the DONE merge effects so experience grows with every completed story.
