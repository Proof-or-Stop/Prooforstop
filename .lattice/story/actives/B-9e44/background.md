## Key Insights
The instrument (packages/main/src/core/playbook-runtime-baseline.ts) was mapped hands-on: generate is deterministic and the seed is CONTENT-INERT (buildBaselineRows takes no seed; records/gold byte-identical across seeds). verify returns status pass|fail plus a ~20-field boolean flag vector (recordsDigestStable, goldDigestStable, manifestDigestStable, staleDetected, requestedProfileMatches, profileRecordCountMatches, partitionContractPass, sourceDigestMutationMatrixPass, ...) AND numeric gold metrics (expectedIdsFoundRate, false-surface rates, malformedRowsSkipped) but NO textual reason. status=pass iff all 19 enumerated conditions hold. Because there is no reason field, truthful adjudication MUST be a frozen per-class fingerprint over an explicit domain (flags + numeric predicates), which is why viability must be two-pronged: a class is fail-closed only if its fingerprint carries a real failure signal; a self-consistent refreshed variant that legitimately verify-accepts is dispositioned to the acceptance bucket, never enumerated as an H2 class. (H2 is the plan tamper-arm hypothesis: every class in the frozen fail-closed set yields status:fail and matches its fingerprint. Enumerating an accept-only class as H2 would mechanically falsify H2.) The existing single-shot tamper smoke that M0 audits for reuse-overlap is packages/main/src/tasks/playbook-runtime-memory-baseline-smoke.ts (gold tamper, corruptRows, recordCount overrides, and manifest-refreshed variants via its refreshManifest helper).
