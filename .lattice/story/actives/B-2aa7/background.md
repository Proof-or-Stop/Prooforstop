## Key Insights

State of main @ 1847b3af6d, verified directly rather than inferred: store.readRedEvidence is a bare readJson at store.ts:852-859, and readJson itself is JSON.parse-and-cast at store.ts:121 with NO schema, NO shape check and NO runtime validation anywhere between parse and the typed domain. That missing trust boundary produces TWO independent crash classes. RECORD class: redEvidenceRecordSatisfied opens at proofstory.ts:932 with record.observedFailure.trim(), so a stored {"id":"corrupt"}, a null or numeric observedFailure, a null record, a string record or an array record all throw a bare TypeError. ENVELOPE class: proofstory.ts:947 assumes records is an array, so records:{} or records:"x" or records:42 throws before any record is examined - a record-only fix passes its own acceptance matrix and still ships this. lattice.config.json sets devGateMode, reviewGateMode and doneGateMode all to enforce, so this aborts a live gate rather than blocking it in a controlled way. Crucially, main carries NO partial fix: the schema classifier that converts some of these to typed errors exists only in the unmerged B-506e worktree, so this story's scope on main is wider, not narrower.

## Solution Tradeoffs

Two orthogonal axes were settled in the audit. Axis A, validation breadth: narrow validation of only the dereferenced field is provably verdict-preserving but leaves the bug latent for the next field a future predicate dereferences; full validation of every mandatory v1 field is stronger but knowingly changes the outcome for records that are schema-invalid yet currently SATISFIED. Full was chosen, which is exactly why the migration scan is mandatory rather than optional. Axis B, rejection form: throwing at the read boundary breaks recoverability, because red_evidence_get and red_evidence_add both read before acting, so a corrupt artifact could be neither inspected nor repaired through the CLI; a silent non-satisfier fails closed but reports nothing, recreating the silent-corruption mode. Quarantine was chosen: mechanically, the validated records array that reaches the typed domain contains only well-formed records, while every rejected entry is retained and reported in a separate malformed list carrying its index, its identifying field if any, and the reason - so the gate fails closed on the evidence while the operator can still see and repair what is broken. A third decision concerns proof method: the five-scenario invariance digest must be DERIVED on main pre-fix and pinned by this story, never imported, because the existing constant belongs to a tree this story is not based on.
