## Key Insights

Current main already classifies each stored record at load: store.readRedEvidence rejects an unsupported per-record schemaVersion with a typed RedEvidenceSchemaError, and the gate predicate skips non-v1 records before touching any v1-only field. That closed exactly ONE class - a record that is null or a bare string. Everything else is still live, verified by probe against current main rather than inferred. RECORD class: classifyRedRecordSchemaSafe returns 'v1' for ANY object lacking a schemaVersion member WITHOUT validating the legacy v1 shape, so a stored record like {"id":"corrupt"}, an observedFailure of null or 123, and an array record (typeof [] is 'object', so the non-object guard misses it) all still reach record.observedFailure.trim() and throw a bare TypeError. ENVELOPE class, wholly untouched: records:{} and records:42 throw a non-iterable TypeError before any record is examined, and records:"x" iterates the STRING'S CHARACTERS and misreports "a record must be an object", blaming a record when the envelope is at fault. ORDERING still decides the outcome: a malformed entry placed after a satisfying one is never examined at all, because Array.prototype.some short-circuits, so the same record set passes or crashes depending on position. The root cause under all of it is unchanged - readJson at store.ts is JSON.parse-and-cast with no schema, no shape check and no validation anywhere between parse and the typed domain. All three gate modes are enforce, so this aborts a live gate rather than blocking it in a controlled way.

## Solution Tradeoffs

Two orthogonal axes were settled in the audit. Axis A, validation breadth: narrow validation of only the dereferenced field is provably verdict-preserving but leaves the bug latent for the next field a future predicate dereferences; full validation of every mandatory v1 field is stronger but knowingly changes the outcome for records that are schema-invalid yet currently SATISFIED. Full was chosen, which is exactly why the migration scan is mandatory rather than optional. Axis B, rejection form: throwing at the read boundary breaks recoverability, because red_evidence_get and red_evidence_add both read before acting, so a corrupt artifact could be neither inspected nor repaired through the CLI; a silent non-satisfier fails closed but reports nothing, recreating the silent-corruption mode. Quarantine was chosen: mechanically, the validated records array that reaches the typed domain contains only well-formed records, while every rejected entry is retained and reported in a separate malformed list carrying its index, its identifying field if any, and the reason. Two further consequences follow from the B-506e merge: the five-scenario invariance baseline is now main's OWN pinned test rather than something to port, and the two-layer read-boundary idiom now exists on main, so this story EXTENDS it to the envelope and to shape-validating the 'v1' residual class rather than establishing it.
