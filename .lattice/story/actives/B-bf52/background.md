## Trigger Event
On 2026-07-18 story B-d877 froze at PLAN with reason `gate-repeat 3>=2` even though every ProofStory gap it had been fixing was a DIFFERENT gap, resolved one after another. The freeze needed a human `story_resume --ack` at a real TTY to clear. The same false freeze recurred on 2026-07-23 in story B-956f when a newly merged acceptance_basis_generate gate produced two different rejection reasons in a row. Probe rp-mrqy5de1 captured the collapse. A direct reproduction against packages/main/dist/core/convergence-breaker.js confirms it: the two real B-d877 rejections (`missing_intent_collision_check` and `missing_red_evidence`, sharing a 200+ character ProofStory preamble) both hash to `story_advance/c70969579c4e`.

## Key Insights
The defect is in gateFailureDigest at packages/main/src/core/convergence-breaker.ts:469-482. Its own doc comment at :463-468 states the intent precisely — reasons that differ only in INCIDENTAL detail should collapse — so reasons that differ in SUBSTANTIVE detail collapsing is a defect against the function's stated contract, not a design choice. Four collapse classes are reproducible today: (C1) `.slice(0, 200)` at :479 drops everything past 200 normalized characters, and ProofStory gap lists routinely share a longer preamble; (C2) the path regex `/\/[^\s"']+/g` at :475 rewrites ANY slash-bearing token, so the phase pair DEV/REVIEW and DEV/TEST both become `dev#`; (C3) the same regex is greedy from the first slash, so src/core/alpha.ts and src/core/beta.ts both become `src#`; (C4) the bare-number regex `/\d+/g` at :476 runs inside identifier tokens, so CHK-001 and CHK-002 both become `chk-#`. The existing guard in packages/main/src/tasks/convergence-breaker-smoke.ts:180-182 does assert that distinct reasons do not accumulate, but its fixtures are the eleven-character strings `reason ALPHA` and `reason BETA`, far too short to reach the truncation and containing none of the four collapsing token shapes — a guard whose fixture cannot exercise the failure.

## Solution Tradeoffs
Hashing is length-agnostic, so the truncation buys nothing a bounded rejection message needs; removing it is the direct fix, with a large sanity bound retained only to cap CPU on absurd input. The normalizer must stay aggressive enough that genuine retries of the same failure still collapse, otherwise the breaker stops firing at all and a runaway agent regains an unbounded retry loop — that is the real risk of this change and the reason the story carries an explicit regression-guard deliverable alongside the precision deliverable. The chosen shape narrows each over-broad rule instead of deleting it: the path rule matches only machine-specific absolute roots (/Users, /home, /tmp, /private, /var, /Volumes) so repo-relative paths and slash-bearing identifiers survive, and the numeric rule matches only standalone numbers so identifier-embedded ordinals survive. A validated seven-case matrix (four must-differ, three must-still-collapse) shows the narrowed rules satisfy both directions. The alternative of digesting a structured failure code instead of the message text was rejected as a much larger change that would require every rejection site to emit a code first.

## Conversational Texture
This defect was found by driving the repro-first program itself: it froze two stories in the same week and each unfreeze cost a manual pty ack, so it is the highest-friction known workflow bug still open. It is being fixed before the remaining program stories precisely because every one of them must pass the same gates that trigger the false freeze. The fix is deliberately narrow — the breaker keeps its threshold, its counters, and its reset semantics untouched, and only the key it counts under becomes precise.
