## Key Insights
The gate is a PURE function returning {advisories: string array; block: ParallelDecompositionBlock or null} from scope facts (the story, its active peers, their ScopeContractData, and a ParallelGateConfig). It must NOT enforce cfg.mode; enforcement is the caller canStartDevGuard job in Story 5. The four block reasons (section 4.3) are provable scope contradictions, never should-have-parallelized judgements: overlap_declared_parallel (tier-1 literal-path intersection with an active parallel peer; tier-2 shared-prefix is only an advisory), broad_glob_unprovable_parallel (a BROAD glob asserted parallel; hard block ONLY when cfg.broadGlobBlocks else advisory), fake_dependency_chain (depends on a peer P citing a symbol provably absent from P.allowedCreate AND no overlap; a plausible-but-false citation degrades to advise), and peer_contract_unreadable_parallel (a peer asserting parallel whose ScopeContractData is missing or unreadable).

## Solution Tradeoffs
A new file core/parallel-decomposition-gate.ts (not the frozen contract parallel-decomposition.ts) keeps S2 disjoint from S3 (audit-config.ts) and S4 (lattice-parallel-wave.ts plus story-review.ts) so the four impl stories are genuinely parallel; Story 5 later reconciles the contract to re-export. Active-peer filtering reuses the terminalPhases = {DONE, DISCARDED} set from parallel-policy.ts (single source). The gate emits the first and most-severe block but ALL advisories. It is pure and hermetically unit-testable (no I/O; contracts passed in as a Map).
