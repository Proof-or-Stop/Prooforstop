## Key Insights
The analyzer is the adjudication layer the earlier milestones deliberately did NOT do (run-batch/tamper only PRODUCE and shape-guard evidence). Three-state (pass|fail|inconclusive) is essential: absent or insufficient evidence must NEVER silently read as pass — it must be inconclusive (or fail). H1 = pairwise digest+metric equality within each scale in batch-ledger; H2 = every tamper verdict's status/fingerprintMatch/dispositionMatch conforms to its frozen class; H3 = resume-reconciliation dupTotal 0 / gapTotal 0 / finalMultisetMatch true; H4 = every proof record within the budget cap (any over-cap without a budget_cap stop is a fail). The report carries a reproducible digest so a second party (Codex host-2) can re-derive it byte-for-byte from the same committed inputs, offline — the campaign's final trust anchor.

## Solution Tradeoffs
Offline-only (read committed evidence, never re-run the instrument or the CLI) keeps M4 deterministic and cheap, and cleanly separates 'produce evidence' (M1-M3) from 'adjudicate evidence' (M4). The digest is over canonicalJson(report minus digest) — the same preimage discipline M2's recordDigest uses — so replication is exact. Reusing lib/instrument.mjs's sha256/canonicalJson avoids a second hashing convention. The three-state logic is the only real complexity and gets a dedicated un-gameable selfcheck (tampered/truncated/missing evidence must not yield a false pass).
