## Key Insights
Both packages/main/src/core/usage-ledger/summary.ts (deriveRecordTotal / UsageSummary) and diagnostics.ts (asKnownDimensions / aggregateByGroup) use a four-field identity (input+output+cacheCreation+cacheRead) where ANY null dimension makes the whole record unknown (never inferred as 0), so it is counted in unknownCount and excluded from providerReportedTotal and the known rollups. The openai and gemini adapters set cacheCreation=null BY DESIGN (these providers structurally never report a cache-write count), so EVERY codex/gemini provider-reported record is bucketed as unknown. The tokens are on disk but invisible in every summary/diagnostics aggregate. The provider-reported validator already guarantees inputTokens and outputTokens are non-null, so a primary (input+output) total is always known for a provider-reported record regardless of the optional cache dimensions.

## Solution Tradeoffs
Preferred: add a NEW additive aggregate — primaryReportedTotal (input+output, known whenever both PRIMARY dimensions are known, independent of the optional cache dimensions) — to summary.ts (UsageSummary) and to diagnostics.ts (per storyId/phase/agentType/model/provider rollups plus overall), kept DISTINCT from the strict four-field providerReportedTotal. This surfaces codex/gemini input+output WITHOUT inferring cacheCreation and WITHOUT touching providerReportedTotal/known/cost semantics. Alternative rejected in this story: a documented adapter rule that cacheCreation is a known 0 for cache-less providers — but cacheRead can still be null when prompt_tokens_details/cachedContentTokenCount is absent, and it mutates the strict four-field meaning, so the additive primary-total approach is cleaner and lower-risk. Cost stays derived from the four-field known totals only — never from the primary total — so no inference leaks into pricing. The usage-ledger zero-cross-module-import invariant must stay intact.

## Conversational Texture
The operator cares that the dollars/tokens spent on codex and gemini are actually visible in diagnostics, not silently dropped into an unknown bucket — while the audit guarantee that we never invent a number a provider did not report must be preserved exactly. So acceptance focuses on: codex and gemini provider-reported finals contribute to the new primary aggregate; the strict four-field providerReportedTotal still excludes them; and anthropic/claude records (all four dims known) appear in BOTH aggregates.
