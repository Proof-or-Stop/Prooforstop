## Trigger Event
On 2026-06-18, while driving story B-a4e3 (koala cleanup), the autonomous driver hit this bug: running the INIT_CHECK bootstrap from a worktree cwd made the framework attempt a nested `git worktree add .worktrees/B-a4e3/.worktrees/B-a4e3`. The user asked to fix it as its own story.

## Key Insights
worktree.ts:430 resolveBootstrapGitRoot returns getRepoRoot() when no gitRoot is configured; getRepoRoot() (worktree.ts) is `git rev-parse --show-toplevel` with cwd=root. `--show-toplevel` from a linked worktree returns the WORKTREE, not the main repo, so the new story worktree is created under the current worktree (nested). The correct primitive is `git rev-parse --git-common-dir`: from any linked worktree it returns the main repo's .git, whose parent is the true main repo root (the same primitive worktree.ts already uses at ~:538 for the worktree registry). This is the gitRoot defect class (wrong-root-from-worktree-cwd) recurring in the bootstrap path specifically.

## Solution Tradeoffs
Approach A (chosen): resolve the main repo root via `git rev-parse --git-common-dir` (absolute, parent-of-.git) in the bootstrap root resolution, so bootstrap always creates the worktree under the main repo regardless of cwd; fall back to the existing behavior when not in a git repo. Keep plain-main-repo + wrapper-root paths byte-identical. Approach B (reject bootstrapping from a worktree cwd with an error) was considered but is more brittle (legitimate flows may bootstrap from varied cwds) and does not fix the underlying wrong-root resolution; A is more robust. Approach C (rewrite the whole worktree resolver) is out of scope. Risk: changing root resolution could affect the wrapper-root (configured gitRoot) path; mitigate by keeping the configured-gitRoot resolveStorySignedWorkspace branch intact and only correcting the no-gitRoot fallback + verifying both yield the main root, with a regression proving non-nested creation from a worktree cwd and byte-identical behavior from the main repo.
