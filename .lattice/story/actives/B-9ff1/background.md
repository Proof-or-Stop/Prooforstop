## Key Insights
The envelope is where an operator's claim becomes machine-checkable, so every admissibility rule has to be enforced at schema time rather than discovered at run time. Three properties make the RED signals here un-gameable. First, the entropy formula is exact and total: entropyBits(value) = byteLength(value) times H, where H is the empirical per-byte Shannon entropy — TOTAL bits, not per-symbol — so a short high-variety string and a long low-variety string are both measured honestly, and an implementation that computes per-symbol entropy produces provably different admissibility verdicts on a fixture table. Second, the minimum-specificity rule is a CONJUNCTION of a length floor AND an entropy floor, so an implementation using OR admits matchers the spec forbids; a differential table over the frozen default policy distinguishes the two. Third, a class matcher can never be the sole present-in-red evidence, which means a candidate envelope carrying only a stderr-nonempty matcher must be rejected — an envelope that would otherwise accept any failing run whatsoever. The digest is equally pinned: assertionDigest is CANON over the assertion subobject INCLUDING policyDigest and EXCLUDING assertionDigest itself, so a validator that forgets to strip the field, or that omits policyDigest, produces a different digest on the same envelope.

## Solution Tradeoffs
Validation is schema-time and fail-closed: an envelope combining expectedExitClass timeout-is-failure with a script-exit adapter linkage is REJECTED at schema time rather than deferred to a run, because the incompatibility is decidable from the envelope alone and spending a run on it wastes the very resource the subsystem exists to protect. Path validation for supplementaryArtifact targetArtifactRef is syntactic — absolute paths, empty segments, dot, dot-dot and backslash segments are rejected — because realpath cannot classify a path that does not yet exist, which is exactly the RED case. Rejections carry the section 1.6 tags so a caller can tell the failure kinds apart: R1-1 for a missing target-exercised proof, R1-2 for a below-threshold or class-only matcher set (the minimum-specificity failure), R1-3 for matcher and path BOUNDS violations (a schema-bounds failure, explicitly including path validation — it is not a specificity tag), and R1-6 for an unregistered or mismatched target binding. The story terminates at a read-only red_evidence_envelope_check(storyId, assertionFile) command that follows the verified house pattern of the existing read-only checkers acceptance_topology_check, topology_critic_receipt_check and proofstory_gate_check in packages/main/src/cli/command-catalog.ts (anchored by command name, not by line number, because that file drifts): it validates a candidate envelope against the resolved policy and the story's registered binding BEFORE a run is ever spent. On success it reports the computed assertionDigest, the matched binding reference and the resolved policy digest, so the operator has what they need to proceed. Registering a read-only operator pre-flight is not a new query surface added to satisfy an enforcement need, so it sits outside the section 5.5 fence; this story records that reasoning explicitly so a reviewer does not re-litigate it.

## Conversational Texture
The assertion file itself is authored by the operator by hand against the documented schema; no generator is in scope here, and the pre-flight command exists precisely so that hand-authoring is safe. Deliberately reserved for later leaves: the disposable-workspace runner that spawns processes and captures streams, run receipts and stream framing, and the green-confirm writer. This story validates envelopes and never executes one. It also does not alter any gate verdict, gate wiring or enforcement mode — the new command is read-only and advisory by construction.
