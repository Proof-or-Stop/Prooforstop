## Key Insights
The envelope is where an operator's claim becomes machine-checkable, so every admissibility rule has to be enforced at schema time rather than discovered at run time. Three properties make the RED signals here un-gameable. First, the entropy formula is exact and total: entropyBits(value) = byteLength(value) times H, where H is the empirical per-byte Shannon entropy — TOTAL bits, not per-symbol — so a short high-variety string and a long low-variety string are both measured honestly, and an implementation that computes per-symbol entropy produces provably different admissibility verdicts on a fixture table. Second, the minimum-specificity rule is a CONJUNCTION of a length floor AND an entropy floor, so an implementation using OR admits matchers the spec forbids; a differential table over the frozen default policy distinguishes the two. Third, rule 3 says a class matcher can never be the sole present-in-red evidence, which means a candidate envelope carrying only a stderr-nonempty matcher must be rejected — an envelope that would otherwise accept any failing run whatsoever. The digest is equally pinned: assertionDigest is CANON over the assertion subobject INCLUDING policyDigest and EXCLUDING assertionDigest itself, so a validator that forgets to strip the field, or that omits policyDigest, produces a different digest on the same envelope.

## Solution Tradeoffs
Validation is schema-time and fail-closed: an envelope combining expectedExitClass timeout-is-failure with a script-exit adapter linkage is REJECTED at schema time rather than deferred to a run, because the incompatibility is decidable from the envelope alone and spending a run on it wastes the very resource the subsystem exists to protect. Path validation for supplementaryArtifact targetArtifactRef is syntactic — absolute paths, empty segments, dot, dot-dot and backslash segments are rejected — because realpath cannot classify a path that does not yet exist, which is exactly the RED case. Rejections are returned as tagged R1-1, R1-2, R1-3 and R1-6 results so a caller can distinguish schema violation from specificity violation from binding mismatch. The story terminates at a read-only red_evidence_envelope_check(storyId, assertionFile) command that follows the verified house pattern of acceptance_topology_check (cli/command-catalog.ts:2581), topology_critic_receipt_check (:2610) and proofstory_gate_check (:2754): it validates a candidate envelope against the resolved policy and the story's registered binding BEFORE a run is ever spent. Registering a read-only operator pre-flight is not a new query surface added to satisfy an enforcement need, so it sits outside the section 5.5 fence; this story records that reasoning explicitly so a reviewer does not re-litigate it.
