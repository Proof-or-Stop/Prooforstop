None are production bugs. CORRECTED root causes (established empirically by running each smoke from repo-root cwd vs a clean /tmp cwd on a fresh build): authority-job-loop-live already passes on a current build (stale-dist snapshot). autopilot-authority is NON-HERMETIC (the original triage label of stale-assertion was wrong): from repo-root cwd it fails with shadow.status=pass != warn, from /tmp it passes; buildAuthorityStatus reads the dev real authority_trust.env via fileReader from cwd, and for shadow mode that real URL leaks in and suppresses the URL-empty warning. The 5 timeouts pass standalone (44-50s) but historically exceeded the 60s manifest cap under parallel load; the manifest already carries raised finite timeouts for all five. Every fix is test-or-manifest-only.

## Solution Tradeoffs
Approach A (chosen): per-smoke minimal fix — rebuild-verify (authority-job-loop-live), no-op fileReader isolation to make it hermetic (autopilot-authority AND multi-host-authority, keeping every existing assertion incl. shadow.status===warn), and re-verify the already-present finite timeoutMs ceilings for the 5 slow ones (bump only if still tight). No production change, no assertion weakened — the hermetic fix removes ambient-env leakage, not coverage. Approach B (env-gate-skip the authority smokes) was rejected for the hermetic ones — they CAN and should run (they test off-by-default machinery in-process without live env); skipping would lose coverage. Approach C (delete the slow smokes) rejected — they are correct, just slow. Approach D (weaken the autopilot assertion warn->pass per the original triage) rejected — it would break the smoke from a clean cwd / CI and hide a valid no-URL warning. Risk: a timeout bump masks a future real slowdown — mitigated by finite measured ceilings (not infinity) and these staying in --full where a true hang still surfaces.
