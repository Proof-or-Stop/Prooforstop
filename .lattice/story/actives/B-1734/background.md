## Key Insights
The build currently has NO locking: B-fb7b fully reverted its scripts/build-lock.mjs attempt, and the shipped scripts/ensure-dist.mjs documents its existence-only reuse limitation and defers the fix here. The four Codex findings, all recorded in B-fb7bs cross_host_review verdicts, split into LOCK bugs -- (1) an mtime-age-based stale-lock steal age-steals a LIVE long-running build; (2) a check-then-delete reclaim TOCTOU race lets two waiters both enter the critical section and one delete a successors live lock -- and FRESHNESS bugs -- (3) single-file mtime freshness misclassifies deleted-source orphans, partial/interrupted builds, and tampered non-index outputs as fresh; (4) existence-only reuse (the minimal form B-fb7b shipped) reuses a present dist with no freshness proof. Crucially, a robust content-bound freshness gate ALREADY EXISTS: scripts/full-suite-build-binding.mjs exports verifyBuildBinding, which sha256-hashes all of packages/main/src plus tsconfig plus package.json (sourceDigest) and all of packages/main/dist (distDigest), so it already detects orphans, partial builds, and tampering for packages/main.

## Solution Tradeoffs
ADD (not replace -- none exists now) a cross-platform mutex via the proper-lockfile library (mkdir plus mtime heartbeat; works on Mac/Linux/Windows, unlike POSIX-only flock which would need a native module). It fixes both LOCK bugs by construction: the heartbeat keeps a live holder fresh so it is never age-stolen, and its reclaim is race-safe. For freshness, reuse verifyBuildBinding as the skip gate (skip only when it verifies) instead of mtime/existence, and add an analogous packages/utils binding whose sourceDigest also covers the packages/main/dist it links against. This makes rebuilds rare (only on a genuine source change), which closes the rm-during-read window. There are three distinct build call sites to unify: scripts/ensure-dist.mjs (the pretest), scripts/build-main-with-binding.mjs (which IS the packages-main-build validate command via npm --prefix packages/main run build), and the packages/utils build. Deliberately NOT doing atomic-publish/symlink dist-swap (YAGNI; Windows symlink permissions are fragile).

## Conversational Texture
The maintainer approved this unified design in-session and accepted adding the proper-lockfile dependency, choosing the cross-platform option so the pipeline works if Windows is ever a target.
