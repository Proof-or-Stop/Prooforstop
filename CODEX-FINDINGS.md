   **Proof:** The repository's DONE-required policy runs the package build and then the root `npm test` (`lattice.config.json:144-146`). That test chain runs both `test:lattice-residue` and `test:proof-or-stop-prompt-baseline` (`package.json:15`, `package.json:19-20`). The prompt-baseline verifier pins a literal `templateHash` for every role template (`scripts/verify-proof-or-stop-prompt-baseline.mjs:44-113`), so CHK-003's planned edits to the 16 agent templates necessarily invalidate the approved manifest. Separately, runtime and gate consumers still embed the old brand or old filenames (`packages/main/src/core/lattice-brand.ts:4-5`, `packages/main/src/handlers/session.ts:777`, `packages/main/src/handlers/validate-docs-drift.ts:57-65`, `packages/main/src/handlers/review-preflight.ts:85-91`, `.githooks/pre-push:147-150`). None is merely prose.

   **Concrete change B-cdf6 must make:** Add CHK-005, titled approximately **“Migrate and re-attest brand-coupled runtime and gate contracts.”** Its context/acceptance must explicitly require: (1) change the canonical runtime product/primary-bin constants while retaining `lattice` only as the deprecated executable alias; (2) remove hard-coded old-brand runtime headings; (3) make docs-drift understand the new primary command and fail closed against an empty-primary extraction; (4) migrate the residue script's preflight caller, npm script, labels, and smokes atomically if the script is renamed; (5) resolve the pre-push package-identity predicate explicitly; (6) review and update every affected approved prompt `templateHash`, rather than weakening or skipping the baseline; and (7) prove `proof-or-stop --version`, the deprecated `lattice --version`, REVIEW preflight, docs-drift mutation cases, `npm run test:proof-or-stop-prompt-baseline`, and the configured DONE-required build plus root suite all pass from the built artifact.

2. **[high] After the documented command rename, docs-drift becomes vacuously blind instead of rejecting bad `proof-or-stop` commands.**

   **Proof:** The extractor claims and implements only ``lattice <cmd>`` matching (`packages/main/src/handlers/validate-docs-drift.ts:29-34`, `packages/main/src/handlers/validate-docs-drift.ts:57-65`). The blocking `missing` list is populated only from that extracted set (`packages/main/src/handlers/validate-docs-drift.ts:90-97`). If CHK-003 changes every example to `proof-or-stop`, extraction returns an empty set: a nonexistent `proof-or-stop definitely_not_a_command` is never added to `missing`. Registered commands merely flow into `stale` (`packages/main/src/handlers/validate-docs-drift.ts:99-105`), which the contract explicitly labels advisory/non-blocking (`packages/main/src/handlers/validate-docs-drift.ts:23-26`). Thus the gate can report no missing commands precisely when all active command documentation has moved beyond its parser.

   **Concrete change B-cdf6 must make:** Replace the brand-specific extractor with an explicit primary-plus-deprecated-alias command matcher, make the expected primary-token extraction non-vacuous for the active CLAUDE/AGENTS input, and add mutation smokes proving (a) a valid `proof-or-stop` command passes, (b) an invalid `proof-or-stop` command fails, (c) an intentional deprecated `lattice` example remains checked, and (d) an all-renamed document cannot silently degrade to zero extracted primary commands. Update the function/provider names and diagnostics where they are user-visible; do not merely add `proof-or-stop` to an allowlist.

4. **[high] Renaming the package identity without updating the hook silently disables the repository's pre-push safety gate.**

   **Proof:** The hook documents `@lattice/core` as its self-repository discriminator (`.githooks/pre-push:24-25`) and exits success whenever `packages/main/package.json` has any other name (`.githooks/pre-push:147-150`). Therefore a broad brand mapping that changes the package name but omits the hook does not fail loudly; it reclassifies this repository as external and bypasses the rest of the hook.

   **Concrete change B-cdf6 must make:** Put the package name in CHK-001's mapping table with an explicit `FROZEN` or `RENAME` verdict. If frozen, add a regression assertion explaining why the hook predicate remains correct. If renamed, change the hook discriminator and its tests in the same commit, and prove both cases: the renamed self-repository executes/fails closed on a deliberately failing gate, while a genuinely external package still takes the intended bypass. Also update the hook's user-facing command examples and rejection text to the new primary binary while retaining only clearly labeled alias guidance.

5. **[medium] The CLI will continue to identify itself with two old brands even if the executable alias and Markdown are renamed.**

   **Proof:** The canonical runtime brand object still declares `LATTICE_PRODUCT_NAME = 'Proofbound CLI'` and `LATTICE_PRIMARY_BIN = 'lattice'` (`packages/main/src/core/lattice-brand.ts:4-5`), and `session_brief` prints the literal heading `# lattice session brief` rather than deriving it from that object (`packages/main/src/handlers/session.ts:772-777`). Meanwhile the current CLI reference simultaneously calls the product “Proof-or-Stop,” “Proofbound CLI,” and says `lattice` is the only active command (`docs/CLI.md:1-5`). A user following the renamed docs would therefore still see old-brand runtime output and contradictory canonical documentation.

   **Concrete change B-cdf6 must make:** Make the approved mapping the single runtime source for product name and primary executable, derive user-facing headings/help/version text from it, and keep the old executable only as an explicitly deprecated alias. Update snapshot/smoke assertions for invocation through both names and require the primary invocation's output to contain no accidental `Proofbound CLI`/bare product-brand `lattice` text; frozen role IDs and `.lattice/` paths must remain distinguishable from product branding.

Those lines are user-readable documentation, not a runtime identifier. Leaving them untouched makes the repository tell users the old command remains primary.

Preserve genuinely historical release names only when marked as historical/frozen, but update present-tense installation and command guidance to `proof-or-stop`, with `lattice` mentioned only as a deprecated alias.
